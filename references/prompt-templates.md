# 提示词模板

这些模板给 agent 用。原则：**脚本给事实，模型给解释**。不要改写脚本算出的答案、链接、页码。

## 0. build 前问用户（缺字段时）

```text
开始前我需要确认 4 个字段，不能替你猜：
1) 科目/科目画像（脚本识别候选：{{candidates}}；置信度 {{confidence}}）
2) 复习天数 N（不是考试倒计时，除非你确认按倒计时算）
3) 目标分（0–100）
4) 材料与往年题的路径；每天可用分钟
如果考试日期与 N 不一致，请明确以哪个为准。
```

## 0.1 五册生成（build）

```text
按 state 里的 subjectProfile / quantification / schedule / questions 生成五册。
硬约束：
- 02 主册、03 答案册、05 刷题宝典使用同一套题号，零缺失零多余；
- 02 不放答案；03 的每题必须有答案、步骤、评分点、校验状态；
- 04 每点 ≤5 行，按最后 3 个有知识点的学习日排序；
- 05 只放题号，按画像题型分组，先“识别信号 → 解法套路”；
- 来源页码只能来自 state 的 source.page；查不到写「待确认」。
```

## 0.2 fill 回填

```text
只填 fill_tasks.json 里出现的 id，不要新增/删除 id。
- main:K* → 2–4 句讲解（类比、定义/条件、正例/反例）；至少 24 字，可带〔原文：文件 第 N 页〕
- answer:Q* → 至少 2 步、15 字的解析、评分点、易错点；没有官方答案就标“模型给出⚠️”
- rubric:Q* → [{"point":"可判分动作","score":2}]，分值合计等于题目 points
- cheatsheet:K* → ≤2 行易混对比 + 口诀
- drill:T* → 识别信号、解法套路、常见陷阱
- kpMap:Q* → 知识点 id 列表（最多 3 个）；不确定就留空
- generate:D01-S02 → 一道符合该题位题型/分值的题：{question:{stem,type,kind,points,kpIds,answer,solution,rubric}}
禁止“略/自行补充/同上/见教材”；引用页码只能来自材料，查不到就不写。
输出 {"tasks":{"main:K1":"...","rubric:P1-Q1":[{"point":"...","score":2}],"generate:D01-S02":{"question":{...}}}}。
```

## 1. 知识点讲解（替换 `today` 里的 `<!-- MODEL: ... -->`）

```text
你在给一个零基础学生讲「{{K 编号 标题}}」。
来源：{{原文：文件 第 N 页}}；目标等级：{{L0-L4}}。
按顺序写：
1) 一个生活化类比（不超过 3 句）；
2) 准确定义/公式，标出每个符号的含义与适用条件；
3) 一个正例、一个反例（反例要说明错在哪一步）；
4) 与相邻概念的一句话区别（只写最容易被混淆的那一个）。
不要给练习题答案；不要写“显然”“众所周知”。
```

## 2. 难点精讲（D 分前 3）

```text
知识点：{{标题}}；当前 D={{D}}；构成：往年失分 {{}} / 错误率 {{}} / 前置深度 {{}} / 易错标记 {{}}。
目标等级：{{L2/L3/L4}}。
请写：
- 最常见错法（具体到哪一步，禁止写“粗心”）；
- 易混概念对 A vs B（各一句区别）；
- 一道 2 分钟内能做完的最小例题（答案放当天文末）。
```

## 3. 生成缺失题目（`status: needs_generation`）

```text
生成一道「{{题型名}}」的{{基础/真题/拔高/背诵}}题，用于 {{K 编号}}。
要求：
- 若为真题：必须来自题库中未使用的真题；没有就标“需人工提供”，不要伪造年份/题号。
- 若为基础/拔高/背诵：自编，但要在题干后标「自编」。
- 给出：题干、答案、逐步解析、评分点、易错点、预估用时。
- 优先在 `fill --tasks` 里找 `generate:<slotId>` 任务，把题目对象填回 `question`；`fill --apply` 会入库并绑定题位。只有补录单题时才用 `coach.py add-question --source model --slot D01-S02 ...`。
```

## 4. 答案重算

```text
题目：{{题干}}
官方答案：{{officialAnswer 或“无”}}
请只做一件事：把题目转成可脚本校验的 `check` 规格。
可用校验器由画像 checkers 决定：通用 choice/exact/numeric；数学 matrix/determinant；
计算机系统画像另有 twos/decode/ieee754/ieee754_decode/flags/modrm/machine。
运行 `coach.py calc --spec '...'` 得到结果，再运行 `set-check` + `recompute`。
若无法转成规格：标 ⚠️「未脚本校验」，不要声称已核验。
官方与重算冲突时：先标 pending，核对 `check` 规格无误后，让用户确认 `--use official` 或 `--use recomputed`；不要默认以重算为准。
```

## 5. B 站匹配理由

```text
只根据 `coach.py bilibili` 的输出写理由，不得新增视频/时间点。
格式：标题命中 a/b 个锚词；分P 命中；字幕锚词覆盖；定位到 P{{page}} 的 {{mm:ss}}。
没有达到阈值：只写“未找到高重合视频”+ 搜索链接，不写“建议看某 UP 主”。
```

## 6. 每日收尾

```text
用 3 句话总结今天：
1) 今天真正学会了什么（只写作答验证过的）；
2) 哪个点仍然不稳（引用错题号/D 分/当前等级）；
3) 明天第一件事（具体到 K 编号/题号）。
不要重复当天全文。
```

## 7. 质检（对应 `coach.py audit`）

```text
你是阅卷组长 + 出版编辑。只输出问题清单，不重写全文。
A 内容：画像题型每类≥3 次？真题覆盖≥90%？三册题号一致？解析有中间步骤？
B 链接：每个 BV 都能在检索缓存找到？有没有编造的分P/时间点？
C 溯源：每个 K 点有文件/页？🟢 标签能在原文命中？
D 量化：60/70/80/90/95 矩阵是否随目标单调？放弃清单是否列出？
E 排版：表格溢出？代码块等宽？目录页码 0 误差？
返修优先级：答案错 > 缺题 > 量化/排期 > 排版。
```

## 8. 急救 / 压缩 / 长线

```text
N≤3：取消构建期，按往年题频率排序，只保留累计覆盖约 80% 分值的题型。
先列：保留哪些题型、放弃哪些内容、每类给一道代表题。
4≤N≤7：构建+强化合并为压缩期，先保证高频题型，再补基础。
N>30：构建期分两轮，第一轮铺面，第二轮按 D/F 补洞；不要把所有新内容堆到最后。
明确告诉用户“放弃的部分不会在本次复习中出现”，不要假装全覆盖。
```
