# 质检门槛与回归测试

## 1. 自动门禁（`coach.py audit`）

| 类别 | 检查 | 失败级别 |
|---|---|---|
| 排期 | 每类题型 ≥3 次且 ≥3 个不同天（急救模式 ≥2/≥2） | 必须修复 |
| 排期 | 每天用时 ≤ 预算（最后一天允许 +30 分钟） | 必须修复 |
| 排期 | 最后一天有 10 模拟 + 2 证明 | 必须修复 |
| 复习 | 所有复习日 < 考试日 | 必须修复 |
| 链接 | 渲染文本中的每个 BV 都在 `videos[]` 或 `.cache/bilibili` | 必须修复 |
| 答案 | 有官方答案 + 重算 + `conflict` 的题必须在解析说明 | 必须修复 |
| 来源 | 每个 K 点有文件/页或标「待确认」 | 提醒 |
| 材料 | 未解析材料要列出状态与原因 | 提醒 |
| 覆盖 | 每个题型至少一道题；每个章节至少一个 K 点 | 提醒 |

`audit` 退出码：0 = 无「必须修复」；1 = 有问题。

## 2. 测试门槛（`python -m unittest discover -s tests -v`）

| 测试 | 断言 |
|---|---|
| 排期 20 天 | 16 类 × ≥3 次 × ≥3 天；最后一天 10+2；每天不超预算 |
| 急救 3 天 | `emergency=True`；覆盖类型 ≤8；每类 ≥2 次/≥2 天 |
| FSRS | 稳定性单调、due 不越考试日 |
| 关键词 | 四源来源可解释；`x86-64` 不被长度过滤；父子互斥；不足用标题兜底 |
| B 站 WBI | 官方 mixin 向量与 `w_rid` 向量一致 |
| B 站过滤 | 负面词/跨领域结果被淘汰；主锚词必须命中 |
| B 站链接 | 输出 BV 必须来自 fixture 检索；不出现未检索的 BV |
| 字幕 | 窗口定位从第一个命中 cue 开始 |
| 解析 | DOCX/PPTX 可读；Markdown 页码标记；代码块里的 `#` 不当章节 |
| 题目 | 分节重号自动加后缀；答案按出现顺序分桶 |
| CLI | init → status → plan → today → answer → audit → export 全绿 |

## 3. 抽检（人工/模型）

- 任选 3 天：每个 K 点的〔原文〕标签能否在对应文件页码找到？
- 任选 3 条 B 站链接：BV 号、分 P、时间点是否与接口返回一致？
- 任选 3 道有官方答案的题：重算结果与解析是否一致？冲突题是否写明？
- 急救模式：是否明确列出放弃内容？
- 弱模型跑一天：有没有编造命令、链接、页码？

## 4. 失败降级

| 失败 | 允许的降级 | 禁止 |
|---|---|---|
| 无网络 | 只给搜索链接 | 编 BV 号 |
| 无 Cookie/无字幕 | 标题/分 P 打分，不给时间点 | 编时间点 |
| 扫描 PDF | 标「待 OCR」 | 假装读到 |
| 旧版 Office | 标「待转换」 | 假装解析成功 |
| 无校验脚本 | 标 ⚠️ 未核验 | 声称已重算 |
| 官方答案冲突 | 以重算为准并说明 | 静默抄官方 |
